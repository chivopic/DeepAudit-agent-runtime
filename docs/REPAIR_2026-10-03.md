## 对应验收问题

| 问题 | 本轮处理 |
| --- | --- |
| A1：项目外读取 | 源码加载拒绝文件、目录及目标路径中的符号链接；读取前校验解析后的路径仍在项目内。拒绝项记录到覆盖范围。 |
| A2：输入截断却报完整完成 | 快照返回发现数、加载数、字节数、上限和遗漏原因。超出文件/字节上限、不可读或缺失文件会产生覆盖缺口，报告为 partial。产品任务保存覆盖数据；JSON、Markdown 下载报告包含遗漏原因及源码快照哈希。未完成任务不计算安全评分。 |
| A3：模式命中误报已确认 | 静态模式复查始终为 INCONCLUSIVE，不提高置信度。记录验证方法；常量 eval、参数化 SQL、同文件无关模式都不会确认漏洞。 |
| A4：恢复忽略取消和进度 | run/resume 都保留外部取消检查；恢复通过流式更新发出进度。共享取消文件可由另一进程写入。取消后保留已有分析结果并停止后续文件。 |
| A5：混合源码版本 | 初次运行将源码与覆盖元数据保存为独立制品，任务保存 SHA-256 引用。恢复读取原制品并验证哈希，不重新检出源码。缺失 checkpoint 或没有快照的旧任务明确失败，需新建任务。 |
| A6：并行声明与串行实现不符 | 本轮收敛为串行分析；产品每步处理一个文件，计划明确为 sequential、max_parallel=1。实验运行时仍可将多个串行单元放在一步内。实际并发和角色协作尚未交付。 |
| A7：配置、租约、持久化不完整 | 产品实际读取后端设置，仅支持 file；其他值明确报错。工作进程先取得操作系统文件锁，再准备项目和修改产品状态。持锁进程存活时不会因超时被另一进程接管；节点完成后更新租约元数据。争用者不覆盖状态或清理原任务的事件流。共享取消、持久事件序号及 `/stream` 回放已接入；三份 Compose 配置挂载运行时数据卷。 |
| A8：排除模式被忽略 | 支持 glob、目录和相对路径排除。显式空目标集合不扩大扫描范围，找不到目标时记录遗漏。 |
| A9：产品测试未进 CI | Agent workflow 加入 R1、R2 产品测试、新增回归测试和事件管理测试。 |

## 使用约束与未完成验收

- 所有 API worker 必须共享同一主机上的 `AGENT_STATE_DIR`。操作系统锁保护当前运行，`expires_at` 仅是租约元数据；进程退出后操作系统释放锁。此机制没有交付跨主机调度。
- 取消是协作式的，正在进行的模型调用可能先完成。设置 file 以外的产品持久化后端会报错，不再静默忽略。
- `agent_runtime_data` 卷保存 checkpoint、SQLite、源码制品和事件。已有容器中的历史文件需要随部署迁移；本轮没有重建容器或移动现有数据。
- 旧任务没有可校验源码快照时，需要新建审计。已完成的旧记录没有批量改写。
- 产品图的 PostgreSQL 恢复、Docker 验证、真实并发/角色协作、RAG 和产品 MCP 尚未完成。2026-10-08 合并保留了主线的通用 PostgreSQL 检查点与独立沙箱服务。
- 本轮没有调用真实模型，也没有验收真实数据库与登录浏览器的完整流程、容器重建恢复或 PDF 导出。

2026-10-02 的验收报告保留为历史记录；本文件说明后续修复及实际验证范围。
